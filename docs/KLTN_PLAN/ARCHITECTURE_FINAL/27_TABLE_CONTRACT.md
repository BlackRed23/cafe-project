## U1 — exact storage obligations and candidate failures

Required logical record, **with physical owner still MISSING**:

`(scope TEXT, commandKind TEXT, callerKey TEXT, actorId TEXT FK User, canonicalVersion INTEGER, requestHash CHAR(64), expectedVersions, outcome, httpStatus INTEGER, resultVersion INTEGER, frozenResponse, committedAt TIMESTAMPTZ, typed subject/result links)`.

Identity must be unique `(scope,commandKind,callerKey)`, independent of requestHash. Historical subject/actor deletion must be RESTRICT or retention-safe pseudonymization; JSON cannot be the sole FK store. Response persistence includes the original status/body and returned identifiers, not a recomputation from current state. The scope/command endpoint dictionary, retained rejection classification, response-size/PII policy and source-version representation also need a field-complete contract.

Candidate receipt columns used for evaluation: `scope`, `<command>Key`, `<command>ActorId`, `<command>CanonicalVersion`, `<command>RequestHash`, `<command>Outcome`, `<command>HttpStatus`, `<command>ResultVersion`, `<command>Response`, `<command>CompletedAt`. Concrete K1/K2 witness: Ingredient I starts name Z/version1. K1 sets A and returns `{id:I,name:A,version:2}`. K2 sets B and returns version3. Restart. Replay K1 must return name A/version2, with no write; changed K1 payload C must produce 409. Current I has B/version3. A last-key slot contains only K2. Hashes of K1 without its response cannot reconstruct the exact result. No stock movement, Agent run, receipt, payment event or recipe version occurred. Locking alone preserves none of the lost information.

Unbounded-sequence witness: for arbitrary n, issue distinct K1…Kn edits, intermixed with distinct rejected stale-version commands, retaining required outcomes. For every i≤n, replay Ki after restart must recover Ri. An N-slot representation fails at n=N+1. Encoding the sequence in a growing JSON/text field requires a fully designed, legitimate journal owner and relationship enforcement; it is not a proof by serialization. Natural event rows grow only when their actual domain events occur. **No evaluated responsibility-preserving existing-table mapping passes this witness. U1 UNSOLVED.**

Required protocol if a legitimate representation is supplied: authenticate and check current access before exposing any receipt; serialize absent keys with transaction-scoped key locking plus authoritative uniqueness; compare hash under lock. Commit effects+terminal result atomically. Required business rejections commit a retained terminal rejection with zero effects (validate before effects or roll effects back to a savepoint); infrastructure rollback is not falsely recorded as a business success. Same-key contenders wait then re-read, different hashes never mutate. At most three confirmed-rollback attempts. After unknown commit, wait for authoritative transaction/key resolution, then retrieve result or prove rollback before retry; no blind re-execution. Retain identities/results for business-history lifetime, not a short cache TTL. These are obligations, not implemented guarantees; without a physical owner none is proven end to end.
