Cross-domain lock protocol to validate, not assumed deadlock-free: current authority rows (sorted IDs), genuine AgentExecution if relevant, Order, PurchaseRequest, count/receipt parents in fixed rank/ID order, Product, supplier/mapping rows, sorted Ingredient rows, sorted IngredientBatch rows, sorted allocation rows; Payment paths Order→Payment→Callback. Discovery reads must be revalidated under locks; inventory ownership determines every stock mutation. A dependency trace from every writer must demonstrate no reverse acquisition or hidden post-lock ingredient discovery.

Domain functions own state transitions; narrow DB guards enforce matching FKs, sums and immutability at commit. Runtime roles cannot directly modify protected balances/events, disable guards or call unsafe functions; function owner/search_path/EXECUTE grants need explicit manifests. CHECK constraints alone cannot validate arbitrary cross-row aggregates. No client typecheck or mock test proves these properties.

No matrix row claims deployed enforcement. GVHD/formal review, safe migration authorization, actual catalog/grants and real database evidence remain independent gates.
