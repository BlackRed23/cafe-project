## Chosen architecture

`AgentWorkflow.dispatchTool(trustedActor, name, input, version)` -> optional `BusinessPort.toolRegistry` -> shared `createToolRegistry` -> canonical `TOOL_CONTRACTS` -> bound mock/backend Business Service -> strict output validation -> returned ToolOutcome/evidence.

- Single schema/metadata source: `apps/agent/src/workflows/tool-contracts.ts`. API contract module is a re-export of the same object. Shared dispatch implementation: Agent `tool-registry.ts`; API adapter module re-exports it. Agent declares exact existing Zod 4.4.3 dependency; lockfile records declaration, no new version introduced.
- Each definition includes name, version 1.0.0, input/output Zod schemas, permission, READ/CALCULATION/WRITE, status, binding slot, timeout/retry policy and error codes. Factories bind service functions to those slots; capabilities reports actual bound/unbound state by mode. Absent bindings fail BLOCKED, never fall back to mocks.
- All five P1 named API handlers now delegate to same dispatch implementation; compatibility exception behavior preserved through facade. No schema validation copied into API.
- Existing workflow reuses existing BusinessPort and AgentWorkflow class. New method handles one explicitly requested tool call only. No planner, graph, execution loop, model, scheduler or new Agent framework.
- Existing seven-entry `TOOL_REGISTRY` remains legacy step policy, unchanged. Its `execute` loop does not dispatch canonical tools and is not advertised as migrated. New canonical entry is `dispatchTool`; no implicit legacy-to-new alias or silent Plan semantics change. P2 must explicitly choose new plan representation/integration.
- `createBackendWorkflows` attaches mock binding to existing BusinessWorkflows composition. Direct `new BusinessWorkflows` remains unbound until explicit `bindMockTools`; missing registry throws TOOL_REGISTRY_NOT_BOUND.
- `createBackendToolRegistry` binds real API service functions, but does not implement remaining backend BusinessPort methods or bypass existing production guards. Test composing it into existing AgentWorkflow uses injected backend services and mock BusinessPort for workflow permissions; this is dispatch proof, not a complete production runtime.

## Business policy decisions

Policies exported from Agent `tool-policies.ts`. Declarations do not enable BLOCKED tools.

**Sales — policy chosen, handler BLOCKED.** UTC half-open [from,to), ordered and max 90 days. Include only COMPLETED order, PAID payment state, COMMITTED item, positive known quantity and authoritative completion timestamp. Exclude cancelled/voided and fully refunded sales. Partial refunds require line attribution; missing attribution/timestamp blocks result rather than treating it as zero or gross sales. Current backend exposes creation/update/payment fields, not an agreed immutable completion/refund-line history service; mock Sale lacks timestamped quantities. No repository SQL/history guessed, no zero/one fallback.

**Reorder — source rules chosen, final quantity service BLOCKED.** All quantities Ingredient.baseUnit. Aggregate quantity minus reserved is not usable stock. Usable is sum of unexpired eligible batch remaining minus batch reservations; unknown expiry excluded by existing rankEligibleBatches. Test proves aggregate 125 versus usable 15 for same fixture, with legacy target recommendation 185 unchanged. Current backend batch DTO lacks per-batch reservations, so do not allocate aggregate reservations arbitrarily. Demand window/lead time must have backend source identity, version and timestamp; no fallback demand=1 or implicit lead time. Target/pack rules must come from backend policy, never LLM write quantity. Legacy/mock target-deficit and legacy sales/lead-time heuristic are not silently unified. Final strategy still requires business decision and authoritative service.

**Supplier — IMPLEMENTED for canonical binding.** Dedicated Ingredient-only read, active nondeleted Ingredient required; only Supplier.status ACTIVE and deletedAt null retained. Unknown status excluded. Positive finite explicit conversion, matching base dimension, finite nonnegative nonmissing price and whole-piece conversion required. Known units/aliases checked using existing unit-conversion helper; declared factor must match. Explicit nonstandard packaging allowed only with positive supplied conversion to Ingredient base unit. Invalid eligible mapping fails closed. No legacy Product fallback. Existing public supplier list behavior unchanged.

Supplier prices remain references, not confirmed offers; no quote ID/version/expiry/currency confirmation introduced. Estimate excludes taxes, delivery, minimum order and pack rounding. Upstream Number DTO precision remains limitation; Decimal multiplication cannot restore precision already lost.

## WRITE policy — disabled

`DRAFT_PURCHASE_POLICY.enabled=false`. Tool name is intent to prepare request; persistence status **PENDING = request awaiting approval**, not approved/sent. No new DRAFT enum or migration.

- Actor from trusted authentication context. Proposed approval: current ADMIN identity, immutable approval ID and canonical SHA256 binding actor/scope/proposal. No model-supplied role grants authority.
- Source versions cover relevant ingredient/batch/recipe/supplier/price data, capturedAt and expiresAt. Approval/source expiry, revocation and stale source must reject before mutation. Proposed input fields alone do not enforce policy.
- Idempotency identity actor/scope/key; same canonical payload returns immutable stored outcome, changed payload conflicts. Concurrent contenders require one atomic effect/receipt/approval-consumption transaction.
- Durable command receipt must retain immutable success/rejection including absent business-target cases. Mutable domain/AgentToolCall rows and mock snapshots are not substitutes. Receipt ownership remains unresolved under current schema; no table silently added/reassigned.
- UNKNOWN resolves only through authoritative durable receipt. Receipt absence alone is not rollback proof; never blind retry. Restart/concurrency/expiry/revocation/UNKNOWN acceptance evidence absent.

**BLOCKED:** durable approval binding, receipt ownership/persistence, transactional concurrent replay, source freshness and expiry checks. Legacy mock purchasing continues under its existing MOCK_ONLY semantics; canonical WRITE has no handler.
